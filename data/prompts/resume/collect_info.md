# 简历信息收集模板

当你在某个收集阶段时，逐项询问用户。可以一次问多个相关字段以加快流程。对于可选字段，明确告知用户"可跳过"。

---

## Section 1: 基本信息

### 必填

| 字段 | 提问方式 |
|------|---------|
| 姓名 | "你的姓名是？" |
| 性别 | "性别？（男/女）" |
| 出生日期 | "出生日期？（如 1995-06-15）" |
| 电话 | "联系电话？" |
| 邮箱 | "邮箱地址？" |
| 教育经历 | 逐条询问：学校 → 专业 → 学位（本科/研究生/博士生）→ 起止时间（允许"至今"） |
| 自我评价 | "请用 3~5 句话描述你的核心优势，每句聚焦一个方面（技术能力、业务理解、团队协作等）" |

### 可选

| 字段 | 提问方式 |
|------|---------|
| 英文名 | "有英文名吗？（没有可跳过）" |
| GitHub | "GitHub 用户名？（没有可跳过）" |

### 教育经历说明

教育经历可能有多个（本科→研究生→博士），逐个询问。每段收集：学校、专业、学位、起止时间。

---

## Section 2: 技术栈

### 必填

| 字段 | 提问方式 |
|------|---------|
| 编程语言 | "你熟练掌握哪些编程语言？（如 Python, Go, Java）" |

### 可选

| 字段 | 提问方式 |
|------|---------|
| 数据库 & 中间件 | "熟悉哪些数据库或中间件？（如 MySQL, Redis, Kafka，可跳过）" |
| 框架 | "熟悉哪些框架？（如 Django, Spring, React，可跳过）" |
| AI 工程 | "有没有 AI 工程相关技能？（如 LangChain, RAG, prompt engineering，可跳过）" |
| 开发工具 | "常用的开发工具？（如 Docker, Git, CI/CD，可跳过）" |

### 动态扩展

如用户提到未列出的技能类别（如"嵌入式""运维"等），允许新增分类，不限于上述 4 个可选分类。

---

## Section 3: 工作经历

逐段询问，每段包含以下字段。询问完毕后确认"还有下一段工作经历吗？"。

| 字段 | 说明 |
|------|------|
| 公司 | 公司全称 |
| 时间起 | 入职时间 |
| 时间止 | 离职时间，允许"至今" |
| 部门 | 所在部门 |
| 职位 | 岗位名称 |
| 职责 | 至少 3 条，建议 3~5 条。用 STAR 法则（情境→任务→行动→结果），每条约 30~50 字 |

鼓励用户提供具体、量化的职责描述。如用户描述过于笼统，追问具体细节。

---

## Section 4: 项目经历

逐段询问，每段包含以下字段。询问完毕后确认"还有下一个项目吗？"。

| 字段 | 说明 |
|------|------|
| 项目名 | 项目名称 |
| 角色 | 你在项目中的角色（如"后端负责人""全栈开发"） |
| 时间起 | 项目开始时间 |
| 时间止 | 项目结束时间 |
| 项目概述 | 一句话描述项目做什么、解决什么问题 |
| 技术栈 | 项目用了哪些技术 |
| 职责 | 至少 3 条，你在项目中具体做了哪些工作 |
| 成果 | 量化项目成果（如"QPS 提升 30%""用户数增长到 10 万"） |

强调职责和成果要有区分度 —— 职责是"做了什么"，成果是"做成了什么"。

---

## Section 5: 其他信息（全可选）

| 字段 | 提问方式 |
|------|---------|
| 证书 | "有哪些职业证书或认证？（如 AWS SAA、PMP，没有可跳过）" |
| 语言能力 | "语言能力如何？（如 英语 CET-6、日语 N2，没有可跳过）" |
| 爱好 | "有哪些兴趣爱好？（没有可跳过）" |

告知用户这整节全部可选，可以全部跳过直接进入后续阶段。
